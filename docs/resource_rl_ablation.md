# 信息新鲜度与不确定度感知调度：四组同结构消融（大阶段二第二步）

> 独立消融报告。机器可读结果在
> `output/rl_resource/ablation/ablation_report.{json,md}`。
> **结论：§11J 的假设仍未被支持，负结果保留。**

## 0. 与 §11J 的关系

旧 §11J 得到的是**负结果**，但当时闭环**尚未接通**——调度影响不了感知链，
四组的位置 RMSE 完全相同。真闭环（§11K）接通后条件变了，因此本轮在
**新条件下重新检验**同一个假设，而不是沿用旧结论。

重新验证用的判据与 §11J 原始表述一致（**先声明、后执行**）：

> 组合特征组相对主基线，**最差完成率不下降** 且 **资源消耗不增加**。

## 1. 冻结了什么（不得按结果调整）

| 项 | 值 |
| --- | --- |
| 奖励函数 | `resource-rl-reward-v1` |
| Actor-Critic 结构 / 隐藏层 | 共享主干 + 逐节点分类头 + 标量 critic；`[128, 128]`，`tanh` |
| 优化器 | `adam`，`lr=3e-4` |
| 训练预算 | 12 updates × 8 episodes × 24 tick |
| PPO/GAE | `γ=0.99`、`λ=0.95`、`clip=0.2`、`value_clip=0.2`、`entropy=0.01`、`value=0.5`、`epochs=4`、`batch=64`、`target_kl=0.03` |
| 结构化动作 / mask | 逐节点 4 类动作，同一 mask 判据 |
| 闭环 | `plan_controlled_feedback` + `expose_all` 门控 |
| 数据划分 | train `4 场景 × {101,103}`；validation `3 场景 × {211,223,227}`；**test 封存** |
| checkpoint 选择 | 守恒硬闸门 → validation 回报最大 → 代价更小 → 更早 |

每次运行前 `assert_frozen()` **逐项断言**；改任何一项都会直接报错。

**唯一变化的是算法可见输入**：四组同形 104 维，被消融的特征**置零**而非删除。

## 3. 三条必须分开读的发现

### 3.1 不确定度信息有**真实的、可复现的行为影响**

`uncertainty_only` 与 `main_baseline` 从**第 2 个 tick 起动作就不同**，
且整体呈现一次**多目标取舍**（不是噪声）：

* 及时性 0.8330 → **0.8910**（↑）
* 平均等待 1.126 → **1.076 s**（↓）
* 估计质量 0.1790 → **0.2110**（↑）
* 通信 1621 → **427 B**（↓ 74%）
* **代价**：完成率 0.6004 → 0.5270（↓）、过期 31.0 → 41.7（↑）、
  资源消耗 0.4106 → 0.4564（↑）

即：拿到不确定度信息后，策略**少发共享、多做本节点该做的事**，
换来更及时的完成与更好的估计质量，但**牺牲完成数量**。
这与"最差完成率不下降"的判据方向相反，因此**不能**说它"更好"。

### 3.2 在不确定度之上再加新鲜度：**决策层面完全无差别**

`uncertainty_only` 与 `freshness_uncertainty` 的 8 项指标**逐位相同**。
这不是"arm 没生效"——实测两组观测在第 6 个 tick 有 **7 个槽位不同**。
决定性证据：两组策略在全部 3 个验证场景 × 72 个决策步上的
**动作序列逐位相同**。

因此结论是：**在本次预算下，新鲜度特征没有改变任何一步决策**——
不确定度块已经覆盖了它在这批场景里能提供的信息。

### 3.3 只开新鲜度：回报略高但主指标未改善

`freshness_only` 回报最好（−7.500 vs −8.667），但**完成率基本持平**
（0.5980 vs 0.6004）、**最差完成率反而略降**（0.5783 vs 0.5854）。
这是一次 **2 训练种子 × 12 update** 的运行，validation 只有 9 个格子，
差值远小于采样波动——**不构成"新鲜度有用"的证据**。

* `masked_invalid_rate` 为 0 是**构造保证**（采样只在合法集内）；
* `unmasked_argmax_invalid_rate` 0.62~0.64 与

**所有组正式部署必须带 mask**；三个数一起报，不允许只报第一个。

## 6. "额外信息带来的收益" vs "PPO 本身带来的收益"

这两件事**必须分开**，本报告只回答前者：

* **本报告能回答**：在**同一套 PPO、同一预算、同一 episode 序列**下，
  换掉算法可见输入会不会改变结果。→ 不确定度会（有取舍），新鲜度不会，
  组合仍不满足判据。
* **本报告不能回答**：PPO 这个算法本身比规则/优化参考好多少——
  学习回报是自定信号，规则基线不优化它。要做那个比较必须把三者放到
  **同一评价向量**上重跑，**未做**（§11L.9 第 1 条不变）。

## 8. 限制（必须与结果一起读）

1. **不宣称统计显著性**：训练 2 个种子 × 12 update，validation 9 个格子，
   所有差值都是描述性的；
2. `source_inconsistency_indicator` 是**未经概率校准的指示量**，
   **不得**称为"出错概率"或"正确概率"；
3. `load_multiplier` 在此实现为**截止余量缩放**（服务压力），
   不是任务数量倍数（§11L.5）；
4. **test 分区未解封**，也没有用任何测试结果回调选择；
5. 四组**都没有**把动作合法性内化，mask 是承重机制；
6. 训练只用了 4 个训练场景；validation 的 3 个场景分别是交接、
   节点掉线、传感器偏差——**泛化结论仅限于此**。
